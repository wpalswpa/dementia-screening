## 1. 프로젝트 주제

치매 전 단계인 경도인지장애(MCI)는 조기에 발견할수록 개입할 여지가 크지만, 병원 검진에 의존하는 지금의 진단 방식은 접근성이 낮은 고령층일수록 오히려 놓치기 쉽다. 본 프로젝트는 AI Hub가 제공하는 치매 고위험군 웨어러블 라이프로그 데이터(활동·수면 기록, 인지기능 검사 점수 MMSE, 진단 결과)를 활용해, 정상군과 위험군(경도인지장애·치매) 사이에 생활 패턴 차이가 있는지 분석하고, 병원 검사 없이 웨어러블 기록만으로 위험군을 걸러낼 수 있는지 확인하려 한다.

## 2. 프로젝트 목적

본 프로젝트의 목적은 정상군과 위험군 사이의 생활 패턴 차이를 데이터로 확인하고, 그 차이를 실제로 위험군 스크리닝에 써도 될 만큼 믿을 수 있는지 검증하는 것이다.

먼저 그룹별 활동·수면 패턴을 비교하고, 진단에 이미 쓰인 MMSE 점수는 예측 모델에서 제외한 채 정상군과 위험군을 구분하는 모델을 만들어 평가할 계획이다. 모델 성능은 데이터를 여러 번 다르게 나눠 반복 평가하는 방식으로 확인할 예정이다.

다만 AI Hub 가이드라인상 "위험군"에는 경도인지장애(80명)와 이미 증상이 뚜렷한 치매(20명)가 함께 묶여 있어서, 분석에서 나오는 차이가 치매 쪽의 뚜렷한 특징 때문인지, 이 프로젝트가 목표로 하는 경도인지장애 단계에서도 유효한 신호인지 구분해서 볼 필요가 있다. 표본 수도 크지 않은 만큼 결과가 우연이 아닌지도 함께 확인해야 한다. 그래서 프로젝트를 데이터 확보·전처리·검증 단계와 서비스 구현 단계로 나누고, 아래 검증 절차를 먼저 통과시킨 뒤 서비스 구현으로 넘어갈 계획이다.

```text
[1단계] 데이터 확보 → 전처리 → 검증           [2단계] 서비스 구현
──────────────────────                     ────────────────────
① 전처리 결과 점검                             FastAPI 연동
② 경도인지장애만 따로 검증(치매 제외)             결과 화면 구성
③ 사용할 지표 개수 정하는 기준 세우기             외부 API(치매안심센터) 연동
④ 상위 지표가 반복해도 똑같이 나오는지 확인
⑤ 결과가 우연이 아닌지 통계로 확인
        │
        └── ②, ⑤ 통과 시에만 서비스 구현 단계로 진행
```

| 구분 | 핵심 분석 질문 |

| Q1 | 정상/경도인지장애/치매 그룹별로 생활 패턴 — 하루 평균 활동량(걸음수 등)과 수면 패턴(수면효율, 수면단계 비율, 수면 시각의 규칙성) — 은 어떻게 다른가? |
| Q2 | 병원 검사(MMSE) 없이 웨어러블 기록만으로 위험군 여부를 걸러낼 수 있는가? |
| Q3 | 웨어러블 지표 중 위험군 판별에 가장 크게 기여하는 지표는 무엇인가? |

## 5. 데이터 분석 계획

아직 실제 데이터를 내려받아 컬럼을 확인하기 전이라, 구체적인 지표명이나 분석 기법까지는 정하지 않고 라이프로그 데이터를 어떤 관점으로 볼 것인지만 계획한다. 세부 방법은 데이터 확인 후 구체화한다.

| 분석 질문 | 분석 대상 데이터 | 분석 방법(방향) |
| --- | --- | --- |
| Q1 | 활동·수면 라이프로그 데이터 | 그룹(정상/경도인지장애/치매)별로 비교 |
| Q2 | 활동·수면 라이프로그 데이터(MMSE 제외), 진단 결과 | 분류 모델을 만들어 위험군 여부를 예측해보고 성능을 확인 |
| Q3 | Q2에서 만든 모델 | 모델이 예측에 어떤 지표를 많이 활용했는지 확인 |
| Q4 | 같은 라이프로그 데이터, 진단 결과를 정상-경도인지장애로 좁힌 것 | Q2와 같은 방식을 정상·경도인지장애 데이터로만 다시 적용해 비교 |
| Q5 | Q2의 분석 결과 | 결과가 우연이 아닌지 통계적으로 확인 |

## 6. 서비스 구현 방향

이 서비스의 역할은 병을 예방하거나 치료하는 것이 아니라, 위험군을 빨리 찾아내 병원으로 연결해서 중증(치매)으로 넘어가는 시점을 늦추는 것이다. 그래서 서비스도 위험군을 한 번 알려주는 데서 끝나지 않고, 실제로 병원 방문 시점을 놓치지 않도록 이어지게 설계한다. 스크리닝(1단계)에서 위험군으로 판정된 사람이 웨어러블을 계속 착용하며 상태 변화를 지켜보는 것(2단계)까지가, 중증화를 지연시키는 실질적인 경로라고 본다. 이 과정에서 쌓이는 개인별 장기 기록은 상태가 나빠지는 시점을 더 빨리 알아차리게 해줄 뿐 아니라, 모델을 계속 보완하고 요양기관·치매안심센터와 협력할 수 있는 바탕도 된다.

1단계 — 스크리닝: 사용자가 자신의 활동·수면 기록을 입력하면, 모델이 정상군 평균과 비교해 위험군일 가능성과 그 근거를 함께 보여주고, 위험군으로 추정되면 가까운 치매안심센터 정보를 외부 API로 연동해 병원(전문기관) 방문을 안내한다.

2단계 — 웨어러블 연계 모니터링: 스크리닝에서 위험군으로 판정된 사람이 웨어러블 기기를 계속 착용하게 해서 활동·수면 패턴이 실제로 나빠지는지 주기적으로 추적하고, 상태가 악화되는 시점을 놓치지 않고 다시 병원 방문을 권유한다. 이렇게 쌓이는 개인별 장기 기록이 모델 성능 개선과 기관 제휴로도 이어져, 개인·보호자 구독료나 기관용 대시보드 제휴 같은 수익 구조로 연결될 수 있다고 본다.

2절의 검증 절차를 통과한 뒤, 남은 일정 안에서는 1단계(스크리닝)까지 FastAPI로 구현하고, 2단계(웨어러블 연계 모니터링)는 발표에서 병원 연계를 지속시켜 중증화를 늦추는 다음 단계이자 사업 확장 방향으로 제시할 계획이다. 두 단계 모두 이 서비스가 병원 진단이 아닌 참고용 도구라는 점과 학습 데이터의 표본 한계를 결과 화면에서 분명히 알린다.

| 항목 | 작성 내용 |
| --- | --- |
| 서비스 대상 | (1단계) 고령층 본인 또는 보호자, 지역 돌봄기관 종사자 / (2단계 확장) 1단계에서 위험군으로 판정된 사람, 요양기관·치매안심센터 등 제휴처 |
| 서비스 구현 방향 | 활동·수면 기록 입력 → 위험군 여부 예측 → 근거 시각화 → 치매안심센터(병원) 안내(1단계) → 위험군 대상 웨어러블 연동 지속 모니터링으로 중증화 지연 이어가기(2단계, 사업 확장 방향) |
| 예상 주요 기능 | 활동·수면 기록 입력/업로드, 위험도 예측 및 근거 제시, 정상군 평균 대비 비교 시각화, 치매안심센터 위치 안내(지도 포함, 외부 API 연동), 서비스 한계 고지 / (확장) 웨어러블 연동 위험도 추이 모니터링, 개인·기관용 구독형 대시보드 |
