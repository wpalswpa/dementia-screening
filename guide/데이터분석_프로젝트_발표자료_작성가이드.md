# 최종 데이터 분석 프로젝트 발표자료 작성 가이드

> **발표의 핵심**\
> 데이터를 분석하여 **무엇을 발견했는가 → 그 결과를 어떻게 해석했는가 →
> 어떤 문제 또는 필요성을 도출했는가 → 이를 해결하거나 활용하기 위해
> 어떤 서비스를 구현했는가**가 발표 전체에서 명확하게 연결되어야 합니다.

------------------------------------------------------------------------

## 2. 발표자료 앞부분

### 표지

-   프로젝트명
-   프로젝트를 설명하는 한 줄 문구
-   팀명
-   팀원

프로젝트명만 보아도 어떤 데이터를 분석하고 어떤 문제를 다루는지 어느
정도 이해할 수 있도록 작성합니다.

### 프로젝트 일정

프로젝트의 수행 과정을 단계별로 제시합니다. 단순 날짜 나열보다 **주제
선정 → 데이터 확보 → 전처리 → 분석 → 해석 → 서비스 기획 → DB 구축 →
구현**의 흐름이 보이도록 작성합니다.

### 팀원 소개 및 업무 분장

팀원별 역할명뿐 아니라 실제 수행 업무를 구체적으로 작성합니다.

### 목차

PART 1의 대목차 체계를 기준으로 발표의 전체 구조를 제시합니다.

# 01. 프로젝트 개요

## 1-1. 프로젝트 배경

-   왜 이 주제를 선택했는가?
-   어떤 사회적·산업적·생활적 배경이 있는가?
-   왜 데이터 분석이 필요한가?

단순한 관심 분야 소개가 아니라 **분석이 필요한 이유**가 드러나야 합니다.

## 1-2. 문제 정의

프로젝트에서 데이터를 통해 확인하고자 하는 문제를 명확하게 정의합니다.

``` text
현재 어떤 문제가 있는가?
        ↓
데이터를 통해 무엇을 확인할 것인가?
```

## 1-3. 프로젝트 목적

분석을 통해 최종적으로 무엇을 파악하고, 그 결과를 어떻게 활용할 것인지
설명합니다. 이 단계에서는 구현 기능을 자세히 설명하기보다 분석의 목적과
방향을 중심으로 작성합니다.

------------------------------------------------------------------------

# 02. 데이터 수집 및 전처리

## 2-1. 데이터 출처 및 수집

-   데이터 출처
-   데이터 확보 방법
-   데이터 기간
-   데이터 규모
-   필요 시 데이터 수집 과정

데이터는 크롤링, CSV, 공공데이터, Open API 등 프로젝트에 적합한 방법으로
확보할 수 있습니다.

## 2-2. 데이터 구성 및 주요 변수

전체 컬럼을 모두 나열하기보다 실제 분석에 활용한 주요 변수를 중심으로
설명합니다.

-   변수명
-   변수의 의미
-   분석에서의 활용 목적

## 2-3. 데이터 전처리

어떤 전처리를 했는지뿐 아니라 **왜 해당 처리가 필요했는지** 설명합니다.

``` text
데이터 문제
   ↓
처리 방법
   ↓
처리 이유 및 분석에 미치는 영향
```

예: `서울 / 서울시 / 서울특별시`처럼 같은 지역이 여러 표현으로 존재하면
지역별 집계가 분리될 수 있으므로 하나의 표준값으로 통일합니다.

------------------------------------------------------------------------

# 03. 데이터 분석 및 결과

이 부분은 프로젝트의 핵심입니다. 그래프를 많이 만드는 것보다 **분석
질문에 답하고 그 결과를 해석하는 것**이 중요합니다.

## 3-1. 분석 질문 및 분석 방향

프로젝트에서 확인하고자 하는 핵심 분석 질문을 제시합니다.

좋은 분석 질문은 실제 데이터로 답할 수 있어야 하며 프로젝트 목적과
연결되어야 합니다.

## 3-2 \~ 3-4. 분석 결과 ①·②·③

각 분석 결과는 다음 구조를 기본으로 작성합니다.

### ① 분석 질문

무엇을 확인하기 위한 분석인지 질문 형태로 제시합니다.

### ② 분석 및 시각화

어떤 변수를 이용해 어떤 방식으로 분석했는지 설명하고 적절한 그래프 또는
표를 제시합니다.

### ③ 주요 결과

그래프에서 확인되는 중요한 수치, 차이, 패턴, 특징을 설명합니다.

### ④ 결과 해석

단순히 그래프를 읽는 수준을 넘어 다음 질문에 답합니다.

-   분석 결과 무엇을 발견했는가?
-   어떤 차이 또는 특징이 나타났는가?
-   그 결과는 무엇을 의미하는가?
-   왜 이런 결과가 나타났다고 생각하는가?
-   이 결과를 어떻게 활용할 수 있는가?

> 데이터가 보여주지 않는 원인을 사실처럼 단정하지 않습니다. 원인에 대한
> 설명은 데이터 근거 또는 합리적인 추론임을 구분하여 제시합니다.

분석 결과가 3개 이상인 경우 같은 구조로 추가합니다.

------------------------------------------------------------------------

# 04. 분석 결과 종합 및 서비스 도출

이 부분은 **분석 프로젝트와 서비스 구현을 연결하는 가장 중요한
단계**입니다. 분석이 끝난 후 바로 구현 화면으로 넘어가지 않습니다.

## 4-1. 핵심 분석 결과 종합

앞의 여러 분석 결과 중 서비스와 연결되는 핵심 결과를 선별하여
종합합니다.

``` text
분석 결과 ① ─┐
분석 결과 ② ─┼→ 핵심 특징 및 패턴 종합
분석 결과 ③ ─┘
```

## 4-2. 분석 결과 기반 문제 및 필요성 도출

분석 결과가 실제로 어떤 문제 또는 정보 제공의 필요성을 보여주는지
설명합니다.

핵심 질문은 다음과 같습니다.

> **그래서 이 분석을 통해 무엇이 필요하다는 것을 알게 되었는가?**

## 4-3. 분석 기반 서비스 방향 도출

앞에서 도출한 문제와 필요성을 어떤 서비스로 해결하거나 활용할 것인지
결정합니다.

``` text
분석 결과
   ↓
문제 / 필요성
   ↓
서비스 방향
```

학생들은 다음 문장을 명확하게 완성할 수 있어야 합니다.

> **"데이터 분석 결과 \_\_\_\_\_\_\_\_\_\_라는 특징 또는 문제를
> 발견하였고, 이를 해결하거나 활용하기 위해 \_\_\_\_\_\_\_\_\_\_
> 서비스를 기획하였다."**

## 4-4. 분석 결과 기반 서비스 기능 설계

분석 결과와 실제 서비스 기능이 어떻게 연결되는지 제시합니다.

| 분석 결과 | 도출된 문제/필요성 | 서비스 기능 |
| --- | --- | --- |
| 분석 결과 A | 필요성 A | 기능 A |
| 분석 결과 B | 필요성 B | 기능 B |
| 분석 결과 C | 필요성 C | 기능 C |

모든 부가 기능이 분석 결과에서 직접 나올 필요는 없지만, **서비스의 핵심
기능은 분석 결과와 연결되어야 합니다.**

# 05. 데이터 분석 서비스 구현

## 5-1. 서비스 개요

-   서비스명
-   주요 사용자
-   서비스 목적
-   핵심 기능

서비스 목적은 04에서 도출한 문제 및 필요성과 연결되어야 합니다.

## 5-2. 서비스 및 시스템 구성

사용자부터 DB까지 전체 데이터 흐름을 보여줍니다.

``` text
사용자
   ↓
웹 화면
   ↓
FastAPI
   ↓
Oracle Database
   ↓
데이터 조회 및 처리
   ↓
사용자에게 결과 제공
```

외부 API 또는 추가 데이터가 있다면 함께 표시합니다.

## 5-3. 데이터베이스 구축

서비스를 위해 어떤 데이터를 DB로 구축했는지 설명합니다.

-   주요 테이블
-   주요 컬럼
-   필요한 경우 테이블 관계
-   분석 결과가 서비스에서 사용되는 방식

필요하면 ERD 또는 테이블 구조를 활용합니다.

## 5-4. 주요 서비스 기능

기능을 단순 나열하지 않고 **분석 결과와 연결하여 왜 필요한 기능인지**
설명합니다.

## 5-5. 서비스 구현 결과 및 시연

실제 구현 화면과 동작을 보여줍니다. 메뉴를 하나씩 클릭하는 것보다 사용자
상황을 제시하고 서비스가 어떤 정보를 제공하는지 보여주는 방식이
좋습니다.

``` text
사용자 상황
   ↓
조건 입력
   ↓
DB 데이터 조회
   ↓
분석 결과 제공
   ↓
사용자가 얻는 정보 및 가치 설명
```

# 06. 결론 및 기대효과

## 6-1. 프로젝트 주요 결과

프로젝트에서 발견한 핵심 분석 결과와 서비스 구현 성과를 정리합니다.

## 6-2. 서비스 활용 방안 및 기대효과

-   누가 사용할 수 있는가?
-   어떤 상황에서 활용할 수 있는가?
-   분석 결과가 실제 의사결정이나 정보 제공에 어떤 도움을 줄 수 있는가?

## 6-3. 프로젝트 한계

데이터, 분석 방법, 서비스 구현 측면의 한계를 구분하여 제시합니다.

## 6-4. 향후 개선 방향

-   추가 데이터 확보
-   분석 방법 개선
-   서비스 기능 확장
-   실시간 데이터 연계
-   사용자 맞춤화 등

# PART 2. 발표자료 작성 예시

> 아래 예시는 발표자료의 **구성과 분석 결과를 서비스로 연결하는 방법**을

# 01. 프로젝트 개요

## \[슬라이드 5\] 1-1. 프로젝트 배경

### 왜 교통사고 데이터를 분석하는가?

교통사고는 지역, 시간대, 사고 유형 등에 따라 발생 특성이 다를 수
있습니다. 그러나 전체 사고 건수만으로는 사용자가 자신의 지역이나 이동
시간대에서 어떤 사고 특성이 나타나는지 파악하기 어렵습니다.

따라서 교통사고 데이터를 분석하여 **지역·시간대별 사고 특성을 확인하고,
분석 결과를 실제 사용자가 활용할 수 있는 정보로 제공할 방법**을
찾아보고자 하였습니다.

**슬라이드 구성 예시** - 왼쪽: 프로젝트 배경 2\~3문장 - 오른쪽: 교통사고
관련 데이터 또는 대표 이미지 - 하단:
`단순 통계 → 사용자 상황에 맞는 정보 필요` 핵심 문구

## \[슬라이드 12\] 3-2. 분석 결과 ① --- 시간대별 사고 발생 특성

### 분석 질문

> 교통사고는 어떤 시간대에 많이 발생하는가?

### 분석 방법

사고 발생 시간을 시간대별로 구분하여 사고 건수를 집계합니다.

### 시각화

`[시간대별 사고 발생 건수 막대그래프 삽입]`

### 주요 결과 --- 예시

-   17\~19시 구간에서 사고 발생 비율이 상대적으로 높음
-   심야 시간에는 전체 사고 건수가 감소함

### 결과 해석

> 사고 발생은 시간대에 따라 동일하지 않았으며, 특정 이동 시간대에
> 상대적으로 집중되는 특징을 확인하였다. 따라서 사용자의 이동 시간에
> 따라 제공해야 할 사고 정보도 달라질 필요가 있다.

------------------------------------------------------------------------

## \[슬라이드 13\] 3-3. 분석 결과 ② --- 지역별 사고 발생 특성

### 분석 질문

> 지역별로 사고 발생 특성에 차이가 있는가?

### 시각화

`[지역별 사고 건수 또는 사고 비율 그래프 삽입]`

### 주요 결과 --- 예시

-   A지역의 사고 건수가 가장 높게 나타남
-   B지역과 C지역은 서로 다른 발생 패턴을 보임

### 결과 해석

> 지역별 사고 건수에 차이가 나타났지만 인구, 교통량 등 지역 규모의
> 영향을 받을 수 있으므로 사고 건수만으로 특정 지역이 더 위험하다고
> 단정할 수는 없다. 다만 지역별 사고 발생 특성이 동일하지 않다는 점은
> 확인할 수 있다.

------------------------------------------------------------------------

## \[슬라이드 14\] 3-4. 분석 결과 ③ --- 지역별 주요 사고 유형

### 분석 질문

> 지역에 따라 주요 사고 유형이 다른가?

### 시각화

`[지역 × 사고유형 그래프 삽입]`

### 주요 결과 --- 예시

-   A지역: 보행자 사고 비율이 상대적으로 높음
-   B지역: 차량 간 사고 비율이 높음
-   C지역: 이륜차 관련 사고 비율이 상대적으로 높음

### 결과 해석

> 전체 사고 건수뿐 아니라 지역에 따라 주요 사고 유형에도 차이가
> 나타났다. 따라서 모든 지역에 동일한 안전정보를 제공하기보다 지역
> 특성을 반영한 정보 제공이 필요할 가능성을 확인하였다.

## \[슬라이드 21\] 5-3. 데이터베이스 구축

### 주요 데이터 예시

  데이터           활용 목적
  ---------------- ----------------------------
  사고 지역        지역 조건 검색
  사고 시간        시간대 조건 검색
  사고 유형        주요 사고 유형 제공
  사고 건수        조건별 사고 발생 현황 제공
  기타 분석 변수   추가 분석정보 제공

### 데이터 흐름

``` text
원본 데이터
   ↓
전처리 및 정제
   ↓
서비스에 필요한 데이터 구성
   ↓
Oracle Database 저장
   ↓
FastAPI에서 SQL 조회
```

실제 프로젝트에서는 팀이 구축한 테이블 구조 또는 ERD를 제시합니다.

## \[슬라이드 22\] 5-4. 주요 서비스 기능

### 기능 1. 지역 선택

지역별 사고 특성 분석 결과를 사용자가 직접 확인할 수 있도록 지역을
선택합니다.

### 기능 2. 시간대 선택

분석에서 확인한 시간대별 사고 특성을 사용자 이동 시간에 맞게 제공합니다.

### 기능 3. 주요 사고 유형 제공

선택한 지역과 시간 조건에서 상대적으로 많이 나타나는 사고 유형을
보여줍니다.

### 기능 4. 분석 결과 시각화

단순 수치뿐 아니라 그래프와 핵심 요약을 함께 제공하여 결과를 쉽게 이해할
수 있도록 합니다.

## \[슬라이드 23\] 5-5. 서비스 구현 결과 및 시연

### 사용자 상황 예시

> A지역에서 오후 6시에 이동할 예정인 사용자가 해당 조건의 과거 사고
> 특성을 확인하고자 한다.

``` text
지역 : A지역
시간 : 18시
      ↓
조건 입력
      ↓
Oracle DB 조회
      ↓
사고 건수 / 주요 사고 유형 / 분석 그래프
      ↓
사용자에게 관련 사고 특성 제공
```

### 시연에서 설명할 내용

-   어떤 조건을 입력했는가?
-   어떤 DB 데이터가 조회되는가?
-   분석 결과가 화면에서 어떻게 활용되는가?
-   사용자는 이 결과를 통해 어떤 정보를 얻을 수 있는가?

# 06. 결론 및 기대효과

## \[슬라이드 24\] 6-1. 프로젝트 주요 결과

### 분석 결과

-   시간대별 사고 발생 특성 차이 확인
-   지역별 사고 발생 특성 차이 확인
-   지역별 주요 사고 유형 차이 확인

### 프로젝트 결과

> 분석 결과를 단순한 보고서로 끝내지 않고, 사용자가 자신의 조건을
> 선택하여 관련 사고 특성을 확인할 수 있는 데이터 기반 서비스로
> 구현하였다.

------------------------------------------------------------------------

## \[슬라이드 25\] 6-2. 서비스 활용 방안 및 기대효과

### 사용자 측면

사용자가 자신의 지역과 이동 시간에 해당하는 사고 특성을 쉽게 확인할 수
있습니다.

### 데이터 활용 측면

기존 사고 데이터를 단순 통계가 아닌 **사용자 중심 정보 서비스**로 활용할
수 있습니다.

### 프로젝트 측면

``` text
데이터 확보
   ↓
분석
   ↓
해석
   ↓
문제 및 필요성 발견
   ↓
서비스 기획
   ↓
DB 구축
   ↓
서비스 구현
```

의 전체 과정을 연결하였습니다.

## \[슬라이드 26\] 6-3. 프로젝트 한계

### 데이터 측면

-   분석 기간의 제한
-   일부 지역 또는 변수의 데이터 부족 가능성

### 분석 측면

-   지역별 인구와 교통량 등의 차이를 충분히 반영하지 못함
-   날씨, 도로환경 등 추가 영향 요인을 포함하지 못함

### 서비스 측면

-   과거 데이터 기반 정보 제공이라는 한계
-   실시간 사고 및 교통 상황 미반영

# PART 3. 최종 발표자료 체크리스트

발표자료를 완성한 후 다음 내용을 확인합니다.

-   [ ] 프로젝트 배경과 문제 정의가 자연스럽게 연결되는가?
-   [ ] 프로젝트 목적이 명확한가?
-   [ ] 사용한 데이터의 출처와 주요 변수를 설명했는가?
-   [ ] 전처리 내용뿐 아니라 전처리가 필요했던 이유를 설명했는가?
-   [ ] 분석 질문이 명확한가?
-   [ ] 각 분석 질문에 적절한 분석과 시각화가 이루어졌는가?
-   [ ] 각 분석 결과에 **결과 해석**이 포함되어 있는가?
-   [ ] 그래프의 값을 단순히 읽는 수준에서 끝나지 않았는가?
-   [ ] 여러 분석 결과를 종합하여 핵심 특징을 정리했는가?
-   [ ] 분석 결과에서 문제 또는 필요성을 도출했는가?
-   [ ] 서비스가 왜 필요한지 분석 결과를 근거로 설명할 수 있는가?
-   [ ] 핵심 서비스 기능이 분석 결과와 연결되는가?
-   [ ] 분석 데이터를 서비스용 데이터베이스로 구축했는가?
-   [ ] DB에 구축한 데이터가 실제 서비스에서 사용되는가?
-   [ ] 서비스 시연에서 분석 결과가 어떻게 활용되는지 보여주는가?
-   [ ] 서비스의 활용 방안과 기대효과를 제시했는가?
-   [ ] 데이터·분석·서비스의 한계를 제시했는가?
-   [ ] 향후 개선 방향을 제시했는가?
